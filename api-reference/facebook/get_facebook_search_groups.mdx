Search the public web index for Facebook groups by `query`. A page contains at most ten indexed hits, deduplicated to group URLs in source order. `author.ext.search_hit` retains the exact evidence URL, title, snippet and whether it matched a group page or a post inside one. A post title never becomes a group name. Group-page names are index display labels until a detail lookup supplies the native name. Unknown member counts, descriptions, creation dates and privacy stay null.

Use `include=details` to request public About-page enrichment for each returned group. It fills known member count, description, creation date, native numeric ID, privacy/visibility and activity. A numeric response alone cannot corroborate a vanity alias; that lookup remains unfilled and refunded. Group URLs remain usable by the group and group-post operations. Indexed discovery does not prove the group is readable; inspect privacy before attempting posts. Numeric and vanity aliases may recur across pages.

Plain discovery holds one credit. Details holds eleven: one for a nonempty group window plus one per usable fresh enrichment. Cached, failed, deferred and empty-field lookups add no enrichment charge. Empty discovery refunds the base credit; response-cache hits are free. `hydration` reports attempted lookups, cache hits, outcomes, credits and elapsed time. Source cost stays explicitly unknown. No administrator/member identities or generic AI labels are returned.

Return `next_cursor` verbatim with the same query, include, judgment, topic, threshold and fit controls, without page. Cursors expire after one hour; paging stops at page 100, with truncation explicit. Native index continuation is checked, never followed as an arbitrary URL. Details use three workers and a twelve-second deadline; at most ten lookups are attempted. Overall collection is bounded to fifty seconds and 2 MiB source/response bodies.

Parent cancellation covers source reservation, rate checks, fetch/body reads, optional cache work and hydration. It returns `499` with a full collection refund; source/overall deadline failure returns `504`. Individual failed hydration remains uncharged while valid discovery can still return. Cleanup never waits indefinitely, and late allowance acknowledgments cannot start another source request. Already accepted upstream work may still consume its reserved source allowance.

Author/group rows use topical relevance; the post/comment label presets do not apply. By default, each row carries `computed.relevance` against the query. `relevance=score` requests this explicitly; `relevance=filter` also removes judged rows below `relevance_threshold` (default `0.5`, range zero to one, up to six decimal places). Source order and native pagination stay unchanged, with no replacement fetch for dropped rows. Unjudged and `sense=unclear` rows are always retained. The response reports scored, cached, unjudged and dropped counts and IDs. These are uncalibrated judgments over bounded public text, not verified group facts, membership, completeness or measured probabilities.

`judgments=off` or `label=none` suppresses default judgments and omits their keys. Explicit `relevance=score` or `relevance=filter` still runs when requested, including custom-topic pricing. Group Author rows receive topical relevance; post/comment labels such as sentiment and promotion do not apply. A separately requested goal-fit pass still runs.

With explicit relevance, `relevant_to` supplies a different topic of one to 200 characters. It adds a one-credit hold, for a maximum of twelve credits with details. Only fresh successful judgments are charged, at one credit per started 25 rows; cached, short, failed or unjudged rows add zero. Query-topic relevance is free. Filtering every row does not refund a successfully read nonempty source window. Exact page-cache hits and idempotent replays remain free.

Judgment caches bind the topic, group key, actual bounded text, model and methodology version. They expire after one hour; no cached judgment is reused for changed text or another topic. Model IDs, numeric ranges and exact same-item quotation evidence are validated before filtering or billing. Invalid, incomplete or unavailable model output preserves all unjudged rows and refunds the extra judgment hold. Parent cancellation during inference or its reservation refunds the entire request, including the source window.

Set `X-Max-Credits: 0`; it works with a zero customer balance and creates no debit/refund ledger entries. Normal authentication, scopes and release gates apply. Previewing does not activate this disabled adapter.

Use `fit=goal&goal=...` to reduce the visible page without adding customer credits. The goal accepts one to 300 characters. `fit_tokens` is an approximate soft budget from one to 16,000, default 1,500, estimated as serialized item UTF-8 bytes divided by four. First, last, uncertain and unjudged rows remain complete even when they exceed that budget. Useful interior rows are kept when they fit; other interiors become reversible stubs retaining group identity, URL, evidence URL, rank and `held_back: true`. Row order, count, pagination and original collection charge stay unchanged. Invalid, incomplete or unavailable judging preserves every full row.

Before replacing anything, the service writes the full immutable page to a signed five-minute Redis snapshot and confirms readback. Storage failure preserves all rows. `data.held_back` reports held IDs, status/reason, goal, budget/estimate, expiry and a `recall_url`. Open that URL with the same authenticated user and API key to retrieve the full page for zero credits, including at zero balance or `X-Max-Credits: 0`. It contains only the original query and `recall_id`; no source or model is called. Missing, expired, changed-query or foreign-key recall returns an unbilled `404` and never refetches. The snapshot stores the page before goal-fit; rows already removed by an explicit relevance filter are outside that page.

This same-route recall URL is a SocialQuery extension: the published reference promises recall but does not specify its retrieval protocol. Fitted page caches are bound to user/API key and retain the original snapshot expiry. Immutable idempotent replay does not extend snapshot lifetime. Fit and recall responses are private/no-store and omit internal source/fit/recall billing receipts. A recall ID supplements normal API authentication.
