title: "LinkedIn Company People"
openapi: "GET /linkedin/company/people"
---

<Warning>The adapter is locally complete and remains disabled pending sustainable source capacity/economics and combined hosted release acceptance. Enabled code and hosted acceptance are tracked separately.</Warning>

Use a numeric `company_id`, `page` from 1 to 100 or a returned `cursor`, and `limit` from 1 to 10 (default 10). Unknown options, malformed identifiers, incompatible cursors and an `include` other than `profile` return **400** before upstream dispatch. Explicit empty query values are rejected rather than treated as defaults. A valid source window costs **10 credits**. Source failure refunds the entire reservation.

With `include=profile`, the hold is **10 + 4 × limit**, up to **50 credits**. Usable fresh delivered profile fills add four credits each. Cached, unfilled and deferred fills add zero; unused holds are refunded. Unfilled rows retain basic data and `profile=null`. `data.hydration` reports `rows`, `looked_up`, `filled`, `cached`, `unfilled`, `credits_held`, `extra_credits` and `ms`.

The pinned source performs Full-mode profile lookups together with the directory read, without email discovery. The same source order is used for plain and enriched calls. A fill exposes source integer follower counts and sets `author.ext.followers_approximate=false`. Following uses LinkedIn's connection-count convention, explicitly identified by `author.ext.following_metric`. Unknown metadata stays null; no member URN namespace, rounded follower bucket or verification claim is invented. Contacts and background sections are discarded.

Each API window scans **ten source positions** over immutable native pages of **25 records**. A window may cross two native pages. `limit=3` serves at most three eligible rows and skips the rest of those ten positions. Duplicate and current-employer-mismatch rows are excluded without refill, with separate `filter_counts`. History retains clipped and excluded identities. Native totals remain per-page observations rather than an exact workforce census.

Encrypted one-hour cursors bind the user/API key, company, enrichment choice and limit. Retain those options on continuation. The adapter reuses each saved native page; it does not refetch an unstable page to produce adjacent API windows. Missing, altered or expired snapshots fail closed. New native pages can still change order or totals as they are reached. Direct deep pages first corroborate the source range; a proven beyond-end window can return empty. An unscoped empty/error dataset remains an unbilled source failure. Page 100 can report `source_has_more=true` and `pagination_truncated=true` without a cursor. Legacy `lipl1` cursors must restart.

Response and core-profile caches are bound to the requesting user/API key and source identity. Normal response-cache hits and successful idempotent replays cost zero, including with zero balance. `Cache-Control: no-cache` bypasses the response cache while preserving immutable source pages and core-profile caches. Cached source/core fills add no enrichment charge. Responses use `Cache-Control: private, no-store` because they carry owner-bound continuation.

A **55-second overall deadline** bounds rate checks, full-cap reservations, Actor transport/body reads, cache operations and projection. Parent cancellation returns **499 REQUEST_CANCELLED**; the deadline returns **504 UPSTREAM_TIMEOUT**, with full refunds on confirmed settlement. Source caps remain reserved after failed or uncertain execution. There is no automatic retry, refill, capacity allocation or deployment. Local and native evidence does not establish hosted disconnect acceptance.
