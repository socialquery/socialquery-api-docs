<Note>This partial local adapter remains disabled. Unavailable requests return HTTP 503 without consuming customer credits. Local batch support does not establish production readiness.</Note>

Supply exactly one input:

- `url`: one canonical HTTPS LinkedIn `/in/` profile URL, returning one typed partial profile.
- `urls`: one to ten comma-separated full profile URLs, returning `{items, total, requested_count, missing, ...}`. The ten-entry limit applies before deduplication. Canonical `linkedin.com` / `www.linkedin.com` and optional trailing-slash variants collapse before holds and source work. Profiles retain first-input order, regardless of source row order. Even one unique URL in `urls` retains the batch shape.

Both inputs together, empty entries, whitespace, URL credentials, query/fragment state, URNs, paging and unsupported parameters reject before spending. Caller inputs support the bounded raw/canonical UTF-8 identity rules described below.

A single profile reserves and charges **5 customer credits** when valid. A batch reserves **5 per unique input**, charges **5 per returned profile**, and refunds missing profiles. Only the pinned source's explicit identity-correlated `404 / Profile not found` record establishes a missing observation. An all-missing batch returns a fully refunded HTTP **404**. Empty datasets, omitted outcomes, repeated/foreign owners, authorization errors and malformed records fail the entire request and refund; they never turn into an inferred missing profile or a cheaper partial success. `X-Max-Credits` must cover the full potential hold. App/stdio MCP and Python quote the same canonical unique count before dispatch.

Successful and failed idempotent replays retain the recorded outcome, consume zero credits and make no source request. Reusing a key with different inputs conflicts. The aggregate batch reports provider usage once; per-profile batch items omit `provider_cost_usd`, `provider_cost_basis` and `provider_cost_complete` because no individual cost allocation was observed. Provider usage estimates are incomplete and may update after completion.
