<Warning>Implemented locally and disabled pending source capacity allocation and combined hosted release acceptance. Unavailable requests return 503 before source work or customer charges.</Warning>

Search public Quora topics by keyword `query`. `limit` accepts 1–10 (default 10); `time` accepts `all` (default), `hour`, `day`, `week`, `month` and `year`, forwarded to the native search freshness control. Search freshness does not establish topic creation or latest activity. Direct URL targets and pagination are unsupported.

Each item contains native topic ID, name, URL, follower observation and photo metadata. The native TID and opaque GID must agree, as must duplicated name/link/count/photo aliases and source query/type/filter traces. Missing counts and photos stay null. A topic may reuse another topic's thumbnail; `ext.photo_topic_id` records the image-path ID separately, without using it as topic identity. Default icons are marked. Photos are never fetched or certified available, and counts and search relevance are source observations.

A nonempty source window settles five customer credits from a five-credit hold. A completed empty window settles zero and refunds the hold, without proving a topic absent from Quora. Source failure, inconsistent rows, duplicate identities and overflow cannot settle a successful charge. Confirmed failures, cancellation (499) and deadline expiry (504) fully refund; source authentication/quota errors return 503. Immutable idempotent replay performs no source work and adds no charge.

One pinned Apify `fatihtahta/quora-scraper` build `0.8.14` run handles the request, using 512 MiB, a 40-second Actor timeout and a 45-second active request window covering reservation, transport/body reads and projection. Source and output limits are 2 MiB each. No automatic retry, enrichment or asset fetch occurs. Already accepted remote work may finish under its original cap after local cancellation.

The provider requires a **$1 maximum-charge setting** even for small runs. Requests save at most ten records, with a published $0.00099 output-record price. The exception allows only exact pinned, single-keyword Profile/Topic plans under their existing row, memory, byte and deadline bounds; other Actor caps remain unchanged. Reported provider usage is an incomplete estimate, separate from customer credits. The runtime allowance remains zero/unallocated.

Native diagnostics covered a ten-result window, all six filter traces, default and reused thumbnails, and an empty no-match window. Original captures and redacted technical fixtures pass projection, schema and canonical settlement checks. Authenticated API, both MCP clients, Python and disposable SQL use simulated source transport and Redis; shared capacity, real Redis, combined hosted acceptance and deployment remain separate. `complete=false`, `total=null` and `next_cursor=null` describe a bounded window.
