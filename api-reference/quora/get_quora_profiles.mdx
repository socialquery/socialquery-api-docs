<Warning>Implemented locally and disabled pending source capacity allocation and combined hosted release acceptance. Unavailable requests return 503 before provider work or customer charges.</Warning>

Search public Quora profiles by `query`, with `limit` 1–10 (default 10). `time` accepts `all` (default), `hour`, `day`, `week`, `month` and `year`, forwarded to Quora's search freshness control. This is not a profile creation-date or latest-activity filter. Query text is a keyword/name; direct URL targets, pagination and extra enrichment are unsupported.

Each item contains an `author` with native numeric UID, profile URL, display name, public credential (`bio` and `ext.credential`), follower observation and avatar metadata. UID and the opaque source GID must agree; duplicated name/link/count/avatar aliases and source query/type/filter traces must agree. Missing optional credentials, counts and avatars remain null. URL slugs supply `username`, with that basis explicit. Native default avatar placeholders are marked. Avatar URLs are never fetched or certified available, and matching a name does not verify a real-world identity or ownership.

A nonempty source window settles five customer credits from a five-credit hold. A completed empty source window settles zero and refunds the hold; it does not prove a person absent from Quora. Source failure, inconsistent rows, duplicate identities, overflow, cancellation (499) and deadline expiry (504) cannot settle a successful charge. Source authentication/quota errors return 503. Confirmed failures refund fully; immutable idempotent replay performs no source work and adds no charge.

One pinned Apify `fatihtahta/quora-scraper` build `0.8.14` run handles the request, at 512 MiB with a 40-second Actor timeout inside a 45-second active window covering reservation, transport/body reads and projection. Source and output limits are 2 MiB each. No automatic retry or extra source/asset request occurs. Already accepted remote work may finish under its original cap after local cancellation.

The Actor requires a **$1 maximum-charge setting** even for small runs. Requests are limited to ten saved records; its published per-record price is $0.00099. The exception is restricted to exact pinned, single-keyword Profile/Topic plans under their verified bounds. Other Actor charge caps remain unchanged. Observed provider usage is an incomplete estimate, separate from customer credits. The runtime allowance remains zero/unallocated.

Native diagnostics covered the default ten-result window, all six filter settings, placeholder avatars, and an empty no-match search. Both original captures and redacted technical fixtures pass projection, schema and canonical settlement checks. API, both MCP clients, Python and disposable SQL use simulated source transport; that is separate from native source diagnostics, real Redis/shared-capacity acceptance and deployment. `complete=false`, `total=null` and `next_cursor=null` express a bounded search window.
