title: "AliExpress Categories"
openapi: "GET /aliexpress/categories"
---

<Note>Enabled as a bounded beta using the existing Apify journal under the explicitly approved $25 total cap. Historical native/local acceptance is recorded; current hosted acceptance remains pending under the user verification waiver. Sustainable capacity is not certified.</Note>

This parameter-free operation returns the complete published US catalog of the pinned source: 24 sections and their subcategories. The accepted native sample contained 519 subcategories and 224 brand records. Brands are counted in `omitted_brand_count` and excluded from the tree. Root and child names and identifiers are native observations; no intermediate group label is invented from a source key.

Each root has a source section `id`, a name, and `children`. Each child has a numeric frontend `id`, its name, `parent_id`, source key and the separately supplied backend `site_category_ids`. Those three identifier namespaces are distinct. The response does not claim that one namespace can be substituted for another in search, or that the source catalog is AliExpress's complete worldwide taxonomy. `source_sections_complete=true` concerns the 24 published sections; `global_taxonomy_complete=false` and `id_namespaces_interchangeable=false` preserve these limits.

A validated catalog costs one credit; API cache hits are free. The response cache lasts up to 24 hours. Empty, truncated, missing-section, duplicate, inconsistent and failed source catalogs fail with zero customer charge. No product or media link is fetched. There are no country, filter, paging or other query parameters.

One pinned taxonomy-only run is capped at $1, 2,000 rows, 512 MiB and 50 seconds, under a 55-second total request deadline including reservation, transport, body reads and projection. The larger transport bound applies only to this exact pinned plan; ordinary Actor limits are unchanged. The full 100-cent ceiling is reserved from the existing shared non-refilling 2500-cent Apify journal and retained after failures. Usage estimates are not a final invoice. Sustained capacity/economics remain uncertified; current hosted acceptance is pending under the explicit user waiver.
