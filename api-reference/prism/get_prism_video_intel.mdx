Video Intel reads one public YouTube, TikTok, Instagram video/reel or canonical Rumble video URL. comments selects0–50 (default20); zero skips the comment source. include=transcript adds a10-credit hold; empty/omitted include skips transcription. Optional claim is1–400characters and app_demand is true/false. Detail is critical: missing/private/invalid detail fully refunds. Native IDs, parent IDs, privacy, dates and counters are validated. Known zeros stay zero and missing values stay null. YouTube retains its official public channel/video identity, title, description, duration, counters, live/embeddable observations; playback and final duration remain unverified.

Comments use one native top-level page, without replies or a deeper walk. YouTube/TikTok/Instagram select locally by known likes within that scanned page, not global top comments; YouTube's source page is time ordered. Rumble retains one native comment window/order with unknown continuation. Replies are reported counters only. At most50 rows are returned; known IDs, returned positions in the locally ranked sample (native positions for the unranked Rumble window), prefix truncation, source count, native ordering and unknown counters remain explicit. Instagram metadata independently corroborates numeric parent ID and shortcode, including canonical /p versus /reel forms. Rumble detail/comments corroborate both video and numeric IDs. At most three distinct TikTok/Instagram native commenter IDs and lookup handles receive public profile lookups; mismatched/private/missing profiles stay unknown. No bot/authenticity inference. YouTube/Rumble commenter profiles are explicitly unsupported. No author contacts, avatars, media or arbitrary links are fetched.

One optional fixed-host transcript read obtains native captions for YouTube/TikTok/Rumble, with timed segments and native ID echoes. Rumble WEBVTT is parsed from the provider response, never fetched from a returned caption URL. Instagram returns an untimed provider AI transcript, bound to the prior metadata/native child IDs. There is no native-caption-to-AI retry/fallback. Absence, unavailable and skipped remain distinct. Accuracy and completeness are unverified. A nonempty validated transcript retains10; no text, source failure or unsupported native captions refunds10 even if an upstream read consumed its capped allowance. Up to3000 caption segments/30000 source text characters stay bounded by the existing parser and4MiB output limit.

Claim and app-demand options use one existing xAI Chat request over at most one caption, one transcript and ten comment prefixes, each700 UTF-8 bytes. Labels cover exact indices with same-prefix quotes. Claim labels describe whether supplied text supports, opposes or mentions the statement, or is uncertain; they do not verify truth or understand the complete video. App-demand labels cover explicit comment problems/tool requests, not inferred market demand, unique people, willingness to pay or probabilities. Quote memberships/counts are recomputed in code. Model failure leaves source observations available at the source price.

Base5 plus10 only for nonempty transcript text: hold5/15, settle5/15. Usable detail retains5 when optional comments/profiles/model fail. Caller499/global55-second504 fully refund; JSON idempotent replay is free. Metadata/comments/profiles are bounded to12seconds, transcript30seconds and model12seconds within the common deadline. Transcript/comments run concurrently; commenter lookups can overlap the transcript. Quota/transport/body/model/projection/cancellation remain bounded, no retries. HMAC request/evidence/time receipts are fully reprojected. Source cash is unknown; model-reported cost is a known floor, not a full invoice. Existing root0, SC100, YouTube30 and shared xAI0/1RPM ceilings remain unchanged, with no new pool, purchase, key or refill.

With include=transcript, responses stream SSE by default unless Accept:application/json requests synchronous JSON. Accept:text/event-stream explicitly selects streaming with or without a transcript. Existing SDKs request JSON and preserve the same15-credit ceiling. Streaming rejects Idempotency-Key before billing; use JSON for immutable replay. Named start/item events describe provisional work, never final credits. A complete event carries the typed API envelope only after durable SQL settlement; error carries the refunded failure or unknown-settlement receipt. Disconnection prevents new work and refunds the request when cancellation is observed. The local Next lifecycle hook is isolated in tests; actual hosted after()/stream acceptance remains a release qualification. Both JSON and stream gates are disabled pending native source/model quality, eligible sustainable capacity and hosted acceptance.
