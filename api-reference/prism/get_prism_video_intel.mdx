openapi: "GET /prism/video-intel"

<Note>This partial YouTube-only adapter is staged locally and disabled. One native video/five-thread source check succeeded; production remains on release 2026-10-11.120 pending the combined audit.</Note>

Supply one clean HTTPS YouTube watch, youtu.be, shorts or live URL with an 11-character video ID. Only the watch `v` query is accepted; tracking/share parameters, fragments, credentials, ports and other platforms reject before reservation. `comments` is 0–50, default 20. Zero skips comment work. Omit `include` or leave it empty; transcript and commenter-profile legs are unsupported. App-demand inference, claim analysis and streaming are unavailable.

The source reads video detail first, requires the exact requested public video and a valid channel ID, then requests one relevance-ordered top-level comment page. The thread and top comment must both match that video and channel, and the thread must be public. Thread/comment IDs remain separate opaque identifiers. Native source order is preserved without claiming exact global popularity rank. No source token is returned or followed, and no reply, profile, avatar or media fetch occurs.

Video reported comments, source page totals and sampled threads are different observations. Reported replies are not fetched replies. Missing counts stay unknown; explicit zeros remain zeros. Duration, live status and embeddability are source metadata, with no final-length or playback guarantee. Comment text prefers `textOriginal`, otherwise requested plain-text `textDisplay`. It stays untrusted data and is never executed as instructions or sent to a model. Arbitrary author URLs, avatar/media fields and source credentials are omitted from canonical output and independent receipts.

Successful empty comment windows are distinct from unrequested, disabled or failed comments. An unavailable/disabled comment leg sets `partial_failure` while retaining the usable video. Every successful usable-video response holds/settles the flat five-credit base price, including skipped, empty or failed comments. Failed/missing/nonpublic video evidence fails unbilled and does not prove absence. Native error/refund and wider field parity remain pending; the local refund rule is explicit.

One or two fixed-host GETs use the existing restricted YouTube Data API key and free quota. Documented quota cost is one unit per video-list or comment-thread-list call; returned units are estimates, not a verified account balance or final invoice. Runtime capacity stays zero/unallocated with all activation gates false. A 35-second common deadline includes reservation, each source read is capped at 12 seconds/2 MiB, output at 4 MiB and canonical receipts at ten minutes. No source retry, paid fallback, allowance reset or new allocation. Other platforms, transcripts/profiles, claim/app-demand analysis, wider native empty/error behavior, sustainable quota and combined REST/MCP/Python/ledger checks remain unresolved.
