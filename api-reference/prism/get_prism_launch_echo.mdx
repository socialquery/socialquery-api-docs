<Note>Enabled in code for the next combined CLI release. Native source samples and local API/client/SQL acceptance pass; hosted deployment and acceptance are pending.</Note>

Searches one Hacker News window of at most 20 stories, ranks within that window by observed points and samples up to 50 comments from each of 1–5 selected threads (default 3). Optional blogs is one DataForSEO content-analysis search of up to five blog snippets; optional dossier is a public GitHub repository plus five open issues and five releases. The only automatically selected repo is a unique exact repository URL among observed hits; ambiguous matches stay unresolved. Dates filter stories and sampled comments; dated web snippets with unknown publication dates are omitted. Twenty credits normally, ten when fewer than half of selected comment-thread reads succeed, zero on an observed empty HN search. A failed critical HN search errors and is refunded. Comment coverage is successful thread reads, not complete comment history. content_analysis uses at most two comments from each selected thread and five indexed blog snippets, each capped at 1,500 characters. Optional Groq analysis returns per-source relevance, sentiment and themes with exact quotations, plus sentiment counts for relevant samples. It excludes article bodies, author identity and whole-web sentiment claims. Analysis may be empty, unavailable, or not_requested; unavailable analysis does not change the comment-coverage billing rule. Blog results must echo the requested keyword, blog page type and publication-date filters. Publication and index fetch timestamps are exposed separately; task cost comes from the provider receipt. Full-article crawling is outside this endpoint’s documented content-analysis contract. Native data-source evidence and bounded free capacity are recorded separately from hosted deployment and model-quality guarantees.

The native Next.js sample returned twenty HN stories, three successful comment-tree reads, five indexed blogs and a matching `vercel/next.js` dossier. All native data legs passed. One of eleven Groq evidence items contained a non-verbatim quotation; the entire optional interpretation was rejected and `content_analysis.status=unavailable`. No quote matching was weakened or source call retried to obtain a positive result. Twenty data credits still applied.

Both developer composites share one-time, non-refilling source journals: thirty public HN requests, the existing twenty-request GitHub ceiling, thirty integer cents of original DataForSEO free-balance capacity and the existing hundred-request ScrapeCreators pool. Each at-most-five-row blog search reserves three cents before dispatch; the tested task receipt was $0.02418. The API has no per-task maximum-charge setting: the reservation is calculated from the currently verified source pricing and bounded request size, with receipt validation. Optional Groq retains its existing hundred-inference quota and expiry. Missing/corrupt/exhausted journals refuse source work; no automatic initialization, refill, purchase, top-up, paid plan or retry is enabled.

Caller cancellation and hard deadlines cover source/model reservations, fetches, body reads, cleanup and final projection. Late reservations cannot start an HTTP request. Cancellation/deadline failures refund the customer hold; an already dispatched source can still consume its reserved source capacity. Local API, both MCP clients, Python and disposable SQL verify billing, partial refunds, empty critical-launch search, error schemas and immutable replay. Those tests use sanitized native-shaped transports and simulated Redis; they are separate from hosted acceptance.
