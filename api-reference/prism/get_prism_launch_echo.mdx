Implemented locally; production disabled pending combined verification. Searches one Hacker News window of at most 20 stories, ranks within that window by observed points and samples up to 50 comments from each of 1–5 selected threads (default 3). Optional blogs is one DataForSEO content-analysis search of up to five blog snippets; optional dossier is a public GitHub repository plus five open issues and five releases. The only automatically selected repo is a unique exact repository URL among observed hits; ambiguous matches stay unresolved. Dates filter stories and sampled comments; dated web snippets with unknown publication dates are omitted. Twenty credits normally, ten when fewer than half of selected comment-thread reads succeed, zero on an observed empty HN search. A failed critical HN search errors and is refunded. Comment coverage is successful thread reads, not complete comment history. content_analysis uses at most two comments from each selected thread and five indexed blog snippets, each capped at 1,500 characters. Optional Groq analysis returns per-source relevance, sentiment and themes with exact quotations, plus sentiment counts for relevant samples. It excludes article bodies, author identity and whole-web sentiment claims. Analysis may be empty, unavailable, or not_requested; unavailable analysis does not change the comment-coverage billing rule. Full-article content-analysis and narrative parity remain incomplete. Blog results must echo the requested keyword, blog page type and publication-date filters. Publication and index fetch timestamps are exposed separately; task cost comes from the provider receipt. Full-article crawling is outside this endpoint’s documented content-analysis contract. Current provider capacity, native live fixtures, semantic quality and production settlement still require combined verification.
