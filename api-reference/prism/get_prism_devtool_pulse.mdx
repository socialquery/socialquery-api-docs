Independently collects public GitHub metadata with five open issues and five releases, the first 20 HN search hits with three bounded thread expansions, the first Reddit search page with three top-level comment expansions, and up to five indexed developer-blog snippets. Dates filter HN, the returned Reddit sample, and blog publication; the GitHub dossier remains current. Explicit repo anchors identity; otherwise only a unique exact repository link in observed HN/blog results is accepted. Failed sources remain unknown, confirmed repository 404 is observed absence, and successful empty searches remain empty. The published pulse formula uses four activity flags: a release within 30 days; at least three sampled HN stories or 50 points; at least three sampled Reddit threads or 25 score; at least three sampled blogs. Two active flags yield strong, one steady, none with observed presence cooling, and no presence quiet. A missing requested source leaves pulse null. These labels describe a level heuristic, not a measured temporal trend. Optional existing Groq analysis receives bounded public samples and returns quote-grounded feature requests, complaints and expressed sentiment; counts and top groups are recomputed locally. Flat 20 credits; a strict majority of requested data legs failing settles to 10, exactly half still settles to 20, and all failing refunds the full reservation. Optional analysis failure does not affect data billing. JSON only. Native data sources and the optional model protocol have separate acceptance evidence; this does not certify arbitrary queries, model accuracy or hosted behavior.

The native Next.js sample completed all four data legs: twenty HN stories with three comment reads, seven Reddit search rows with three selected threads, five indexed blog snippets and a matching GitHub dossier. All seventeen optional model evidence items passed identity and exact-quotation checks. This is one tested sample, not a model accuracy or time-series trend guarantee. The response envelope permits `credits_used=0` for free idempotent replay while `data.credits` preserves the original settled price.

Both developer composites share one-time, non-refilling source journals: thirty public HN requests, the existing twenty-request GitHub ceiling, thirty integer cents of original DataForSEO free-balance capacity and the existing hundred-request ScrapeCreators pool. Each at-most-five-row blog search reserves three cents before dispatch; the tested task receipt was $0.02418. The API has no per-task maximum-charge setting: the reservation is calculated from the currently verified source pricing and bounded request size, with receipt validation. Optional Groq retains its existing hundred-inference quota and expiry. Missing/corrupt/exhausted journals refuse source work; no automatic initialization, refill, purchase, top-up, paid plan or retry is enabled.

Caller cancellation and hard deadlines cover source/model reservations, fetches, body reads, cleanup and final projection. Late reservations cannot start an HTTP request. Cancellation/deadline failures refund the customer hold; an already dispatched source can still consume its reserved source capacity. Local API, both MCP clients, Python and disposable SQL verify billing, partial refunds, empty critical-launch search, error schemas and immutable replay. Those tests use sanitized native-shaped transports and simulated Redis; they are separate from hosted acceptance.
