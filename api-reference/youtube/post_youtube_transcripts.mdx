---
title: "Batch YouTube Transcripts"
openapi: "POST /youtube/transcripts"
---

Send `ids` as an array of 1–100 bare eleven-character YouTube video IDs. Full watch URLs are rejected. Rows stay in input order. Use `format=text` (default) for joined caption text, or `format=segments` for `start_ms`, `duration_ms` and `text` on every segment. An optional `language` chooses a caption track; the returned `language` retains the provider's trimmed track name when known. Unknown labels remain null. Explicit empty `format`/`language` and unknown options reject before reservation; language codes are limited to 80 characters.

The source is the existing [ScrapeCreators transcript API](https://docs.scrapecreators.com/v1/youtube/video/transcript/). Video identity and segment timings are checked before a row can succeed. Starts and ends must be finite, nonnegative numbers or decimal strings with ordered starts and end at or after start; overlapping captions are allowed. Whitespace, hexadecimal/exponent strings, booleans, sparse segments and contradictory gone-video responses cannot become successful captions or definitive misses. Missing captions and unavailable videos are distinguished only when the source explicitly reports them. A source failure is `error`, not an invented empty transcript.

Billing reserves **3 credits × number of input IDs** and settles at **3 credits per successful row**. `not_found`, `error` and `deferred` rows cost zero. For two IDs, send `X-Max-Credits: 6`. Duplicate input IDs are separate requested rows. The batch is not response-cached; repeat the same `Idempotency-Key` to replay a result without further work or charges. JSON keeps its existing fields and adds `summary`: total, ok, not_found, unsupported, error, deferred, coverage, credits_charged and credits_refunded. Coverage is ok/total; live charged credits match the settled envelope and refunded credits are unused hold. Canonical billing checks any supplied summary. A free JSON replay reports zero current charge/refund in `data.summary`, with top-level `original_summary` preserving the original execution.

At most four source calls run concurrently. A single twelve-second deadline covers each source fetch, body read and JSON parse within a common forty-second source window; no new work starts after the batch's twenty-eight-second scheduling budget. Responses must be JSON and fit 1 MiB. Each transcript has at most 4,000 segments and its entire normalized JSON row must fit 64 KiB of UTF-8, including text, timings, identity and metadata. Oversized captions return an unbilled error; they are never truncated into successful output. Bodies are canceled after timeout/overflow, without waiting on an uncooperative cancellation promise. HTTP quota/auth bodies are not parsed. Ignored aborts and late results cannot hold the batch open or become successful rows. Remaining rows are returned as `deferred` and unbilled. Retry only those IDs in a new batch with a new idempotency key. Provider quota/authentication failures stop new source work. Large batches are not guaranteed to finish in one request.

Canonical billing rechecks every row's identity and order, exact fields, selected text/segment format, timing/text limits, null failed-row data, whitelisted reasons and envelope counts. A tampered count alone cannot turn malformed captions into a charge. Source-cost totals include only validated returned receipts and may omit timed-out or unavailable provider usage; they are not an invoice.

Typed transcript streaming is staged behind `streamEnabled: false`; SSE currently returns 503 before a claim, credit reservation or source work. Once enabled, `Accept: text/event-stream` sends one `data: <JSON>` line and a blank line per message, without a named `event:` field. A result is `{type: "result", key: "transcript", value: {provisional: true, index, row}}`. Input indexes preserve correlation while source completions can arrive out of order. Exactly one `{type: "done", summary}` follows durable settlement. Failure attempts refund before `{type: "error", code, message}` then done; unconfirmed settlement/refund keeps both credit figures null. No start/item/complete chunks are sent.

A nonempty `Idempotency-Key` (up to 256 characters, scoped to account/API key for 24 hours) shares one immutable settled JSON snapshot across JSON and, once enabled, SSE. A transcript snapshot can fit 8 MiB, covering 100 bounded 64-KiB rows; profile/post-stat/comment-lookup snapshots retain 4 MiB. A live stream attempts snapshot storage once after settlement/refund, with a three-second wait. Uncertainty does not reverse confirmed billing or release a claim for immediate duplicate execution; a committed but unacknowledged write can still replay, otherwise the claim stays pending until expiry. Completed, expired or replaced claims cannot be overwritten. Unknown refunds produce no fabricated settled snapshot. A changed body conflicts 409; pending claims return 409.

Stream replay emits committed rows in input order with `provisional: false`, then done with zero current charged/refunded credits. `Idempotent-Replayed: true`, `X-Idempotent-Replay: true` and `X-Original-Request-Id` identify replay. No source calls, fresh holds or ledger mutations occur. Legacy saved JSON without a summary is validated and reconstructed. Valid stored failures replay error/done without inventing an original refund; invalid-input preflight snapshots keep their original JSON status even when SSE was requested. Retry failed/deferred inputs using a new key.

Disconnect suppresses chunks and stops new dispatch. Bounded in-flight reads still finish, settle and attempt persistence. This policy does not establish reference delivery-based refunds. The existing local indexed row/data.items wrappers, native source/field/default coverage, telemetry, reference 45/55-second deadlines and combined deployed REST/MCP/Python/ledger/disconnect verification remain open. Local saved/synthetic tests and disposable claim-SQL checks do not certify real credit-ledger acceptance. Through MCP use `execute_endpoint`; through the Python skill supply `--allow-mutation`, an idempotency key and the full batch credit cap.
