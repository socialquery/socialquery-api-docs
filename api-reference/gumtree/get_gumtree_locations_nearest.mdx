Supply `latitude` and `longitude` together, or `location_coordinate=latitude,longitude`. Coordinates use finite decimal degrees within -90–90 and -180–180. Equal aliases are accepted; conflicting aliases, incomplete pairs and unsupported inputs reject before a credit hold.

The candidate returns one provider-reported nearest Gumtree UK postcode or area. `location` preserves its native `id`, `name`, `type`, `latitude` and `longitude`. Source coordinates can differ from requested coordinates. The response does not establish a radius, road distance, exhaustive directory or independently verified nearest-neighbour accuracy. It is not a general address geocoder. The source describes IDs/types as inputs to Gumtree location filters; live compatibility remains unverified.

A usable success would retain the existing five-credit customer price. Only a documented JSON `NOT_FOUND` 404 with `success=false`, `endpoint_family=location`, `billable=false` and `retryable=false` becomes an unbilled not-found response. HTML 404s, parser drift, malformed records and outages fail without manufacturing an empty result. Known errors never cause retries or provider fallbacks.

One request is bounded to fifteen seconds including capacity reservation, a 64 KiB response and a fixed HTTPS recipient. API keys stay in the source's `x-api-key` header; cookies, redirects and account credentials for other providers are excluded. The verification journal remains zero/unallocated. No signup, API key creation, allowance reset or purchase occurred. `upstream_credits=1` reflects the documented provisional source price, while `provider_cost_usd=null` and `provider_cost_complete=false` preserve unknown cash cost.
