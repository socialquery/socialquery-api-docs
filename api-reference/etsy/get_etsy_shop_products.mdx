<Note>Partial shop-specific adapter staged locally and disabled. One native shop record and three listings corroborated ownership, IDs, USD prices, source positions and reported totals. Exact native shop sorting/page parity, empty/error/non-USD acceptance, sustained capacity and combined verification remain open.</Note>

Supply a public shop name in `id` or a canonical HTTPS Etsy `/shop/` `url`. Both must match if supplied together; numeric shop IDs are unavailable. `limit` accepts 1–36 (default 36), with optional `page=1` and a supported source currency. This is a shop read, not keyword search. The source's search sort is not applied to shops; `sort_by`, later pages and continuation remain unsupported. The Actor's bounded window does not establish Etsy's exact native page size or complete active inventory.

The diagnostic shop reported 183 listings and returned three. Reported totals, shop rating/reviews/sales/admirers and card-level observations remain distinct from product ratings and exact inventory. Native position and dataset emission position are separate; `native_shop_rank` remains unknown and `complete=false`.

Prices retain corroborated source currency, with no local conversion or SKU/final-checkout/shipping guarantee. Detail/review reads are disabled, so product rating, stock, variants, shipping, publication dates and complete galleries stay unknown. Only the primary public image is projected. Canonical badge/ad flags remain null: source flags are retained separately, and default-looking false values are not proof of absence. Shop owner/contact/location and optional enrichment are omitted from response and receipt.

Nonempty validated windows settle five credits. Zero requires an explicit shop record reporting zero listings with no listing rows. Empty datasets, blocked/error responses and nonzero inventory without rows fail without net customer charge. Existing paid Apify credits are authorized; bounded source cost/time and a zero/unallocated runtime journal remain enforced. All activation flags stay false.

Cancellation returns `499 REQUEST_CANCELLED`; expiry of the active source window returns `504 UPSTREAM_TIMEOUT`. The full customer hold is refunded on confirmed settlement. Reservation, source work, fetch and body reads share the same deadline, even when a dependency ignores cancellation or cleanup stalls. Late work starts no later read or retry. A completed success/failure replay keeps its payload and performs no new source or ledger work. Already accepted upstream work may still consume its original capped allowance; cancellation does not guarantee a remote stop or allowance rollback. These lifecycle checks use fixture transport and disposable SQL; the native contract gaps and disabled release state above are unchanged.
